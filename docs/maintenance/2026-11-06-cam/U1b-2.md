## Findings

### U1b2-01 — Whitespace-only x-session-id passes verbatim; x-user-id rejects blank (asymmetry)
`src/capture_proxy/session.py:65-66` vs `:106`
severity: REQUIRED | code: G-EDGE
evidence:
```
65:         if session_id_header:
66:             return session_id_header
```
versus `:106: if user_header and user_header.strip():`.
mechanism: `resolve()` returns a whitespace-only `x-session-id` verbatim (a non-empty string is truthy) as the session id; `resolve_user_id()` strips and treats blank as absent, falling to hash/`anonymous`. Inconsistent blank-header handling across the two namespaces; the whitespace session id reaches the index filename (sanitized downstream at `logger.py:252`).
why-not-intended: AGENTS.md :235-240 treats both headers as "send or absent"; blank values should fall through uniformly.
test_protocol_gap: G-EDGE — no test for whitespace-only `x-session-id` (or any blank-header fall-through).
suggested fix: strip the session header before the truthiness check so blank/whitespace `x-session-id` falls through like `x-user-id`.

### U1b2-02 — User bucket truncated to 64 bits (16 hex chars); distinct keys collide by construction
`src/capture_proxy/session.py:114`
severity: REQUIRED | code: G-EDGE
evidence: `:114: return f"user-{digest[:16]}"` — 16 hex chars = 64 bits.
mechanism: two different Authorization keys can hash to the same `"user-<16hex>"` bucket by construction → distinct users merged into one queryable bucket (fail-open grouping degradation, not an auth bypass). The session path uses 128 bits (`:_hash_to_uuid` `:155-156`), so the asymmetry is real.
why-not-intended: bucketing is intentional grouping, but the collision consequence (distinct users indistinguishable under `index/users/`) is not disclosed as acceptable; docstring `:90-91` states width without noting collision.
test_protocol_gap: G-EDGE — no collision/bucket-width test.
suggested fix: explicitly document the 64-bit width and collision consequence, or widen the digest prefix used for the user bucket.
