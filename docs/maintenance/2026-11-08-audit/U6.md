## Findings

### U6-01 — `capture_last_token_residuals` broad exception catch (activations.py:180-183) [LOW]

file:line: `src/model_headroom/refusal/activations.py:180-183`

evidence:
```python
    except (RuntimeError, ValueError, TypeError, AttributeError):
        return None
```

mechanism: The live-capture forward pass catches only 4 exception types. A
`KeyboardInterrupt`, `MemoryError`, or `torch.cuda.OutOfMemoryError` (subclass
of RuntimeError, so caught) propagates. More importantly, a `transformers`
version mismatch raising `ImportError` inside `model(**encoded)` is not caught
and propagates unhandled. Impact: crash instead of graceful None. Fix: add
`ImportError` and `OSError` to the tuple, or broaden to `Exception` with a
logged warning.

### U6-02 — `capture_residuals_sglang` swallows all errors silently (activations.py:260-261) [LOW]

file:line: `src/model_headroom/refusal/activations.py:260-261`

evidence:
```python
        except (urllib.error.URLError, OSError, TimeoutError, ValueError):
            continue
```

mechanism: Every failed prompt is silently skipped; the caller only sees
`None` if ALL prompts fail. No warning, no count of failures. An operator
whose sglang server lacks `--enable-return-hidden-states` gets no diagnostic.
Impact: silent data loss. Fix: log a per-prompt warning to stderr with the
exception type.

### U6-03 — `report.py` NaN handling in JSON export (report.py:118) [LOW]

file:line: `src/model_headroom/refusal/report.py:118`

evidence:
```python
"cohen_d": None if s.cohen_d != s.cohen_d else s.cohen_d,
```

mechanism: Correctly converts NaN to None for JSON (NaN is not valid JSON).
But `stat.cohen_d` is typed as `float` (not `float | None`), so a NaN
value is technically a float. The conversion is correct but relies on NaN
self-inequality, which is fragile. Better: use `math.isnan()` explicitly.
Impact: cosmetic. Fix: `None if math.isnan(s.cohen_d) else s.cohen_d`.

### U6-04 — `cli.py` `--device auto` resolves to cuda without checking memory (cli.py:330-340) [INFO]

file:line: `src/model_headroom/refusal/cli.py:330-340`

evidence:
```python
    if requested == "auto":
        return "cuda" if torch.cuda.is_available() else "cpu"
```

mechanism: `auto` picks cuda if available, even if VRAM is insufficient for
the model. No memory check. Impact: OOM crash on large models. Fix: document
that `--device auto` prefers GPU; operator must use `--device cpu` for
CPU-only. Not a code defect per se, but a UX gap.

### U6-05 — `cli.py` `torch_dtype` doesn't handle missing config.json gracefully (cli.py:343-352) [LOW]

file:line: `src/model_headroom/refusal/cli.py:343-352`

evidence:
```python
    try:
        with (Path(model_path) / "config.json").open() as handle:
            config = json.load(handle)
    except (OSError, json.JSONDecodeError):
        return "auto"
```

mechanism: If config.json exists but contains a non-dict (e.g., a list or
string), `config.get(...)` raises AttributeError, which is not caught.
Impact: crash. Fix: add `AttributeError` and `TypeError` to the except tuple.
